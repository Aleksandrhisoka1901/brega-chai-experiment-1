## 0. Согласованные границы и продуктовые решения

Результат этой работы ограничен нормативными документами и референсами:

- обновлённые `product-spec.md`, `architecture-spec.md` и `design-spec.md`;
- общий CSS-контракт `design-tokens.css`;
- композиционный `design-reference.html`;
- интерактивный `component-showcase.html` на vanilla HTML/CSS/JS.

Production-компоненты storefront не входят в этот план.

До детализации визуальной системы необходимо синхронизировать следующие решения:

- Hero и «О проекте» имеют независимые необязательные `backgroundColor` и `textColor`;
- значения цветов — непрозрачный `#RRGGBB`; `null` наследует системный token компонента;
- пользовательские цвета не проверяются, не корректируются и не получают frontend fallback;
- гарантия WCAG 2.2 AA распространяется на системную палитру, но не на две пользовательские пары;
- header не sticky; mobile Hero использует порядок «текст → изображение»;
- hash активной секции главной обновляется через `history.replaceState`;
- товар имеет числовой остаток; доступность вычисляется как `stock > 0`;
- количество ограничено диапазоном `1–5` и текущим остатком;
- listing card не содержит счётчика; на товарной странице счётчик активен до добавления;
- после добавления CTA становится активной secondary-кнопкой «В корзине», открывающей drawer; дальнейшее количество меняется только в корзине;
- остаток атомарно списывается при создании заказа и один раз возвращается при `cancelled`;
- статусы заказа: `new`, `confirmed`, `completed`, `cancelled`;
- СДЭК и онлайн-оплата исключены из MVP; checkout создаёт заказ-заявку;
- доставка вводится одним полем «Адрес доставки», её стоимость подтверждает менеджер;
- email необязателен; телефон нормализуется через `libphonenumber-js`;
- rich content использует стандартный Strapi Blocks без ограниченного toolbar; `h1` рендерится как `h2`;
- интерфейсные иконки берутся из Lucide через `lucide-react`; другие UI-icon sets не смешиваются;
- валюта MVP — RUB.

## Цель

Превратить текущую дизайн-спеку из описания визуального направления в исполнимый контракт для дизайна, разработки, наполнения CMS и приёмки интерфейса.

После обновления разработчику не потребуется самостоятельно определять состояния компонентов, допустимые цветовые пары, поведение форм, системную обратную связь и критерии качества.

## 1. Формализовать цветовую систему

Добавить раздел `Color Pairings`:

- разрешённые сочетания текста и фона;
- рассчитанный контраст каждой пары;
- цвета hover, active, focus и disabled;
- варианты CTA на светлом, sage и тёмном фоне;
- контраст системной палитры;
- независимые CMS overrides только для Hero и «О проекте»;
- явное исключение пользовательских цветов из автоматической проверки;
- запрещённые сочетания.

Результат: готовая таблица цветов, которую можно напрямую перенести в design tokens и тесты контраста.

## 2. Дополнить систему токенов

Расширить раздел `Design tokens`:

- fluid typography;
- line-height и letter-spacing;
- максимальные ширины контейнеров;
- breakpoints;
- размеры controls и иконок;
- aspect ratios изображений;
- z-index;
- focus ring;
- disabled-состояния;
- safe-area;
- drawer elevation;
- skeleton colors;
- motion properties.

Результат: практически готовый CSS-контракт.

Токены имеют три уровня:

1. primitive — конкретные значения;
2. semantic — назначение;
3. component — только уникальные параметры компонента.

Breakpoints: `768`, `1024`, `1440px`. QA-viewports не являются breakpoints. Fluid typography интерполируется между `320` и `1440px`. Page shell и обычный контент ограничены `1600px`, текст — `68ch`.

Матрица использует `N/A` для неприменимых состояний. Async-кнопка сохраняет текст и ширину, добавляет spinner и блокирует повторное нажатие. Disabled-ссылки запрещены. Listing card имеет одну интерактивную цель.

## 5. Уточнить формы и checkout

Расширить требования к формам:

- `label`, `name`, `type` и `inputmode`;
- `autocomplete`;
- разрешённый paste;
- обязательные поля;
- загрузка и повторная отправка;
- фокус на первой ошибке;
- сохранение введённых данных;
- предупреждение при закрытии незавершённого checkout;
- поведение клавиатуры на мобильных устройствах;
- единая зона нажатия checkbox и его label.

Результат: проверяемая спецификация checkout-интерфейса.

Checkout остаётся вторым состоянием cart drawer. Черновик хранится в `sessionStorage` текущей вкладки; согласие не восстанавливается. Ошибки впервые показываются после blur, затем обновляются при вводе; submit показывает summary и фокусирует первую ошибку. Повторный submit использует тот же idempotency key.

## 6. Описать карусель и интерактивные панели

Для «Ритуалов», товарной галереи и корзины определить:

- keyboard navigation;
- focus management;
- доступные названия controls;
- объявление изменений;
- scroll snap;
- touch gestures;
- overscroll;
- interruptible motion;
- reduced motion;
- блокировку фоновой прокрутки;
- safe-area.

Результат: точный контракт интерактивного поведения.

Карусель конечная, без autoplay и loop, прокручивается на одну карточку с `scroll-snap: proximity`. Клавиши-стрелки не перехватываются; фокус остаётся на control. Галерея переключается только явной активацией, использует crossfade `240ms`. Cart drawer имеет ширину `460px` на desktop и занимает весь dynamic viewport на mobile.

## 7. Добавить техническую media-матрицу

Зафиксировать требования для каждого типа изображения:

| Слот           | Aspect ratio           | Минимальный размер       | Crop                                | Загрузка |
| -------------- | ---------------------- | ------------------------ | ----------------------------------- | -------- |
| Hero           | адаптивный split       | рекомендация 2400×1600   | focal point, mobile crop опционален | priority |
| Карточка       | `4:5`                  | рекомендация 1600×2000   | cover + focal point                 | lazy     |
| Галерея товара | `4:5`, thumbnail `1:1` | рекомендация 1600×2000   | contain по умолчанию                | mixed    |
| Rich content   | широкий editorial slot | рекомендация в help text | без ручного wide-toggle             | lazy     |
| OG image       | `1.91:1`               | 1200×630                 | safe area                           | server   |

Дополнительно определить:

- допустимые форматы;
- максимальный вес;
- правила прозрачного фона;
- обязательность `width` и `height`;
- alt;
- placeholder;
- поведение отсутствующего изображения.

Результат: изображения можно готовить и валидировать до загрузки в CMS.

Единственное блокирующее ограничение upload — `12MB`. Размеры и пропорции являются рекомендациями в description конкретного Strapi media field. Разрешены JPEG, PNG и WebP; SVG для контента запрещён. Alt хранится рядом с конкретным использованием media.

## 11. Добавить измеримый Design QA

Создать финальный acceptance checklist:

- viewport 320, 390, 768, 1024, 1440 и 1920 px;
- Chrome, Safari, Firefox и Edge;
- отсутствие горизонтального скролла;
- zoom 200%;
- keyboard-only;
- contrast audit;
- reduced motion;
- screen-reader smoke test;
- минимальный и максимальный контент;
- missing image;
- visual regression;
- image/font budgets;
- Core Web Vitals.

Результат: дизайн принимается по воспроизводимым критериям, а не по общему впечатлению.

Visual baselines: `390`, `768`, `1440px`; layout smoke: `320`, `1024`, `1920px`. Браузеры — две последние стабильные версии Chrome, Safari, Firefox и Edge. Данные — фиксированный QA seed. Accessibility объединяет axe-core, keyboard-only, reflow и VoiceOver smoke test. Стартовые budgets: fonts `300KB`, Hero `350KB` desktop/`220KB` mobile, card image `160KB`, LCP ≤ 2.5s, INP ≤ 200ms, CLS ≤ 0.1.

## Критерии завершения

План считается выполненным, когда:

- все новые разделы добавлены в `design-spec.md`;
- правила не противоречат продуктовой и архитектурной спекам;
- ключевые значения представлены токенами или таблицами;
- для каждого интерактивного компонента описаны состояния;
- системные и ошибочные состояния имеют визуальные правила;
- accessibility-требования измеримы;
- media-матрица пригодна для подготовки контента;
- HTML-референс синхронизирован с документом;
- финальный Design QA checklist можно использовать при приёмке.
