# ADR-003: Заказ, остатки и корзина

- Статус: принято
- Дата: 28 июля 2026

## Контекст

Strapi не является готовым commerce backend. Браузерные цена и остаток могут
устареть или быть подменены, параллельные заказы могут конкурировать за один
товар, а повторная отправка формы не должна создавать дубликат. Корзина при этом
должна сохраняться между посещениями без хранения персональных данных.

## Решение

Корзина реализуется собственным store на `useSyncExternalStore`. Версионированный
persist adapter хранит в `localStorage` только минимальный проверяемый Zod-схемой
snapshot товара; цена используется исключительно для предварительного
отображения. Adapter обрабатывает повреждённые данные, миграции и синхронизацию
между вкладками без hydration mismatch.

`POST /api/checkout/orders` является BFF-границей доверия и передаёт
нормализованный запрос одному закрытому Strapi transaction endpoint. Только
Strapi владеет транзакцией PostgreSQL:

1. валидирует payload и anti-bot сигналы;
2. BFF вызывает Strapi со scoped server token;
3. Strapi начинает DB transaction и проверяет idempotency key;
4. внутри неё читает и блокирует строки товаров, повторно проверяет публикацию,
   цены, остатки и количество `1 ≤ quantity ≤ min(5, stock)`;
5. в той же transaction списывает остаток и сохраняет неизменяемый snapshot
   заказа.

Ошибка до commit откатывает и заказ, и stock. Next.js не выполняет отдельного
списания или создания заказа.

Цена хранится как целое число рублей, итог вычисляет только сервер. Idempotency
key имеет unique constraint: одинаковый ключ и payload возвращают созданный
заказ, а одинаковый ключ с другим payload отклоняется. Отмена заказа возвращает
остаток ровно один раз. Переходы статусов задаются domain policy:
`new → confirmed → completed`, при этом `new` и `confirmed` могут перейти в
`cancelled`.

## Последствия

- Клиентскому snapshot нельзя доверять при создании заказа.
- Корзина не резервирует товар; конфликт остатка разрешается при checkout.
- Атомарность заказа и stock должна быть доказана integration-тестами, включая
  конкурирующие запросы.
- Повторные запросы безопасны между процессами; in-memory idempotency store
  запрещён.
- Онлайн-оплата, СДЭК и внешние уведомления не входят в MVP.
