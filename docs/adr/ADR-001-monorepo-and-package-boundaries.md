# ADR-001: Monorepo и границы пакетов

- Статус: принято
- Дата: 28 июля 2026

## Контекст

Storefront на Next.js и CMS на Strapi имеют разные runtime-границы, но совместно
используют контракты товаров и заказов. Проекту нужны единые версии
инструментов, воспроизводимые проверки и возможность запускать приложения
вместе. При этом преждевременный общий пакет UI или утилит создаст лишние
границы сборки и скроет принадлежность кода.

## Решение

Использовать монорепозиторий на Yarn workspaces и Turborepo:

- `apps/web` содержит Next.js storefront, BFF, UI и design tokens;
- `apps/cms` содержит Strapi, его content types, services и policies;
- `packages/contracts` содержит общие DTO, Zod-схемы и чистые domain-функции,
  которые действительно используют оба приложения.

Не создавать заранее `packages/ui` или универсальный пакет `utils`. Код
выносится в новый package только при наличии стабильной границы и минимум двух
потребителей. Зависимости между workspace-пакетами должны быть явными, а
TypeScript работает в strict-режиме.

## Последствия

- Одна установка зависимостей и единый lockfile обеспечивают согласованность
  локальной разработки и CI.
- Turborepo может кэшировать и упорядочивать build, test, lint и typecheck.
- UI можно развивать рядом с единственным потребителем без дополнительного
  public API.
- `packages/contracts` нельзя связывать с браузерным, Next.js- или
  Strapi-специфичным runtime.
- При появлении второго UI-потребителя выделение UI-пакета потребует отдельного
  архитектурного решения.
