# Brega Chai — работа с заказами в Strapi Admin

## Доступ

В разделе Settings → Administration panel → Roles назначаются независимые
действия плагина «Заказы»:

- «Просмотр заказов» — открыть список и карточку;
- «Изменение статуса заказа» — дополнительно выполнять разрешённые переходы;
- «Редактирование заказа» — менять адрес, состав и внутренний комментарий
  менеджера;
- «Удаление заказа» — удалять заказ только после явного подтверждения.

Менеджеру, который только сверяет заказы, достаточно просмотра. Права изменения
статуса и редактирования не следует выдавать автоматически вместе с просмотром.
Доступ к стандартной сущности Order в Content Manager рабочей роли не требуется.

## Обработка заказа

1. Открыть «Заказы» в основном меню.
2. Найти заказ по номеру или имени; при необходимости ограничить статус и даты.
3. Открыть номер заказа и сверить контакты, адрес, комментарий, состав и сумму.
4. При необходимости выбрать «Редактировать заказ»: изменить адрес, количество,
   добавить или удалить позицию и сохранить внутренний комментарий. Перед
   сохранением сверить автоматически пересчитанный итог.
5. Для принятого заказа выбрать «Перевести: подтверждён».
6. После выполнения выбрать «Перевести: выполнен».
7. При отмене прочитать предупреждение и подтвердить действие: остатки
   возвращаются один раз транзакционной commerce-логикой.
8. Для окончательного удаления нажать корзину в конце строки и подтвердить
   действие. У неотменённого заказа остатки возвращаются перед удалением; у
   отменённого заказа повторного возврата нет.

Имя, телефон, email и комментарий покупателя остаются неизменяемым snapshot.
Адрес, состав и внутренний комментарий менеджера можно менять только у заказов
в статусах «Новый» и «Подтверждён». Существующие позиции сохраняют цену на
момент заказа, новые получают текущую цену; суммы и stock пересчитываются
сервером. Если заказ параллельно изменил другой менеджер, команда отклоняется —
нужно обновить карточку и проверить актуальное состояние.

## Диагностика

- безопасная ошибка загрузки не означает изменения заказа — повторите запрос;
- ошибка status action оставляет прежний статус;
- ошибка редактирования оставляет прежние заказ и остатки;
- отсутствие действий означает terminal status либо отсутствие permission;
- application log для перехода или редактирования содержит только document ID,
  статусы при наличии, administrator ID, результат и error code; PII не
  логируется.
